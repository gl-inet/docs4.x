# Не вдається підключитися до сервера WireGuard із маскуванням трафіку {#cannot-connect-to-an-obfuscated-wireguard-server}

Маскування VPN приховує трафік VPN під виглядом звичайного інтернет-трафіку. Деякі маршрутизатори GL.iNet підтримують протокол AmneziaWG, який дозволяє налаштувати сервер WireGuard із маскуванням трафіку.

Якщо не вдається підключитися до такого сервера, виконайте наведені нижче дії для усунення проблеми.

1. **Переконайтеся, що кожен клієнт використовує окрему конфігурацію WireGuard.**

    Кожному клієнту потрібен власний файл конфігурації вузла (peer). Використання однієї конфігурації на кількох клієнтах спричиняє збої підключення.

    За потреби відкрийте **VPN** -> **WireGuard Server** -> **Profiles**, щоб переглянути експортовані профілі.

    ![Профілі WireGuard](https://static.gl-inet.com/docs/router/en/4/faq/cannot_connect_to_obfuscated_wgserver/wg_profiles.png){class="glboxshadow"}

2. **Переконайтеся, що клієнт підтримує перевірку параметрів маскування.**

    AmneziaWG має зворотну сумісність. Якщо сервер WireGuard підтримує лише AmneziaWG v1.0, його конфігурація пройде перевірку під час імпорту в клієнт із підтримкою v2.0.

    Однак якщо файл містить параметри маскування AmneziaWG v2.0, клієнт WireGuard також повинен підтримувати AmneziaWG v2.0. Інакше перевірка параметрів може не пройти.

    !!! tip "Як визначити версію AmneziaWG?"

        **V1.0**: параметри S3-S4 відсутні; H1-H4 — окремі фіксовані цілі числа.

        **V2.0**: це V2.0, якщо виконується хоча б одна з таких умов:

        - Наявні параметри S3-S4
        - H1-H4 задано як числові діапазони
        - Наявні власні параметри I1-I5.

        > Примітка: I1-I5 не створюються автоматично. Користувачі можуть вручну додати їх як окремі рядки до файлу конфігурації, щоб трафік AmneziaWG нагадував інші поширені протоколи, зокрема QUIC або WebRTC.

    Якщо сервер WireGuard — маршрутизатор GL.iNet, перевірте його версію AmneziaWG одним із двох способів нижче.

    ??? note "Перевірка через вебпанель адміністрування"

        1. Увійдіть у вебпанель адміністрування маршрутизатора.

        2. Відкрийте **VPN** -> **WireGuard Server** -> **Configuration** і перевірте параметри маскування. Якщо конфігурація містить параметри **S3-S4** або **H1–H4** задано як змінні діапазони замість фіксованих значень, маршрутизатор використовує AmneziaWG 2.0, як показано нижче.

            ![AmneziaWG 2.0 у вебпанелі](https://static.gl-inet.com/docs/router/en/4/faq/cannot_connect_to_obfuscated_wgserver/awg_2.0_web.png){class="glboxshadow"}

            Інакше він використовує AmneziaWG 1.0, як показано нижче.

            ![AmneziaWG 1.0 у вебпанелі](https://static.gl-inet.com/docs/router/en/4/faq/cannot_connect_to_obfuscated_wgserver/awg_1.0_web.png){class="glboxshadow"}

    ??? note "Перевірка командою SSH"

        1. Увійдіть у маршрутизатор через SSH.

        2. Виконайте `opkg list|grep awg` і перевірте суфікс пакета **kmod-amneziawg** у результаті. Якщо є позначка **2.0**, маршрутизатор підтримує AmneziaWG 2.0, як показано нижче.

            ![AmneziaWG 2.0 через SSH](https://static.gl-inet.com/docs/router/en/4/faq/cannot_connect_to_obfuscated_wgserver/awg_2.0_ssh.png){class="glboxshadow"}

            Інакше він використовує AmneziaWG 1.0, як показано нижче.

            ![AmneziaWG 1.0 через SSH](https://static.gl-inet.com/docs/router/en/4/faq/cannot_connect_to_obfuscated_wgserver/awg_1.0_ssh.png){class="glboxshadow"}

3. **Змініть параметри маскування.**

    Якщо ви вручну задали [параметри маскування](amneziawg_obfuscation.md#parameter-overview), наприклад Jc, Jmin або Jmax, на сервері WireGuard, неправильні значення можуть спричиняти збої рукостискання.

    Змініть ці параметри та повторіть підключення, щоб перевірити, чи проблема пов’язана з їхньою невідповідністю. Також можна відновити налаштування маскування за замовчуванням для перевірки.

4. **Перевірте з’єднання в офіційному застосунку AmneziaWG.**

    Виконайте порівняльну перевірку: встановіть офіційний застосунок Amnezia WG, імпортуйте початковий файл конфігурації, експортований сервером, і спробуйте підключитися.

    - Якщо в офіційному застосунку з’єднання встановлюється, файл конфігурації дійсний. Причина може бути у початковому клієнтському пристрої. Перевірте його мережеве підключення або зверніться до служби підтримки.

    - Якщо з’єднання й далі не встановлюється, проблема може бути пов’язана з конфігурацією сервера VPN маршрутизатора, мережевим підключенням або налаштуваннями міжмережевого екрана. Перевірте ці налаштування та параметри маскування.
