# Маскування трафіку AmneziaWG {#amneziawg-obfuscation}

AmneziaWG — протокол VPN на основі WireGuard із вбудованим маскуванням трафіку. Параметри маскування визначають, як приховується трафік для уникнення виявлення під час обмежувальної перевірки мережі.

Нижче докладно описано AmneziaWG та відмінності між версіями протоколу.

## Навіщо використовувати AmneziaWG? {#why-amneziawg}

Попередник AmneziaWG, WireGuard, зарекомендував себе як швидкий і надійний протокол VPN завдяки компактному коду та високій ефективності. Однак фіксовані заголовки й передбачувані розміри пакетів утворюють легко впізнавану сигнатуру. Системи DPI можуть легко визначати ці пакети та одразу припиняти з’єднання, що є суттєвою проблемою у країнах із суворою інтернет-цензурою.

AmneziaWG успадковує просту архітектуру й високу продуктивність початкової реалізації WireGuard та додає окремий модуль маскування для приховування характерних ознак трафіку VPN. Це допомагає приватним і корпоративним користувачам захищати конфіденційність та підтримувати стабільні з’єднання в мережах з обмеженнями.

Основні можливості:

- Приховування ознак VPN для запобігання виявленню провайдерами, міжмережевими екранами або системами глибокої перевірки пакетів (DPI).

- Маскування з’єднання VPN під звичайний вебтрафік для підвищення стабільності та успішності підключення в мережах з обмеженнями.

## AmneziaWG V2.0 {#amneziawg-v20}

### Огляд {#amneziawg-v20-overview}

<font color="red">**Примітка**: Маршрутизатори GL.iNet підтримують AmneziaWG 2.0 починаючи з прошивки v4.9.0.</font>

AmneziaWG 2.0 зберігає механізми маскування v1.0: послідовність зайвих пакетів (**Jc**, **Jmin**, **Jmax**) і випадкові префікси для пакетів Init і Response (**S1–S2**). Нові механізми приховують ознаки з’єднання, які раніше залишалися передбачуваними:

* **S3–S4**: випадкові префікси для пакетів Cookie і Data. У v1.0 доповнювалися лише пакети Init і Response, тому розмір пакетів Cookie становив рівно 64 байти, а розмір пакетів Data дорівнював розміру корисних даних.

* **H1–H4 як діапазони**: значення заголовка для кожного типу пакета вибирається з діапазону замість використання одного фіксованого числа. Під час приймання допускається будь-яке значення з відповідного діапазону. Чотири діапазони не мають перекриватися.

* **I1–I5**: задані користувачем пакети UDP, які надсилаються перед кожним рукостисканням. Завдяки цьому на початку сеансу трафік нагадує поширений протокол UDP, приховуючи рукостискання WireGuard.

Ці поліпшення ускладнюють виявлення трафіку VPN, зберігаючи високу швидкість і низьку затримку WireGuard.

!!! Tip "Як відрізнити AmneziaWG 1.0 від 2.0?"

    **V1.0**: параметри S3-S4 відсутні; H1-H4 — окремі фіксовані цілі числа.

    **V2.0**: це V2.0, якщо виконується хоча б одна з таких умов:

    - Наявні параметри S3-S4
    - H1-H4 задано як числові діапазони
    - Наявні власні параметри I1-I5.

    > Примітка: I1-I5 не створюються автоматично. Користувачі можуть вручну додати їх як окремі рядки до файлу конфігурації, щоб трафік AmneziaWG нагадував інші поширені протоколи, зокрема QUIC або WebRTC.

### Параметри {#amneziawg-v20-parameters}

| Параметр | Опис | Обмеження | Автоматично створені значення |
| ------------ | ------------------------------ | --------------- | ---------------- |
| Jc           | Кількість випадкових зайвих пакетів перед початком рукостискання клієнтом для перешкоджання виявленню ознак трафіку | 1~128 | 4~12 |
| Jmin         | Мінімальний розмір випадкових зайвих пакетів (байти); задайте разом із Jmax для визначення розміру цих пакетів | 0 ≤ Jmin < Jmax < 1280 | 0 <= jmin < jmax < 1280 |
| Jmax         | Максимальний розмір випадкових зайвих пакетів | 0 ≤ Jmin < Jmax < 1280         | 0≤ Jmin < Jmax < 1280 |
| S1           | Випадкові префікси пакетів Init | 0 ≤ S1 ≤ 1132                  | 15~150 |
| S2           | Випадкові префікси пакетів Response | 0 ≤ S2 ≤ 1188 <br> S1 + 56 ≠ S2 | 15~150 |
| S3           | Випадкові префікси пакетів Cookie | 0 ≤ S3 ≤ 1216                  | 15~150 |
| S4           | Випадкові префікси пакетів Data | 0 ≤ S4 ≤ 32                    | 0~32   |
| H1~H4        | Динамічні заголовки типів пакетів; випадкові значення (v1.0) або діапазони (v2.0) | 5~2147483647; H1, H2, H3 і H4 повинні відрізнятися | 5~2147483647 |
| I1~I5        | Пакети-сигнатури для імітації протоколів | довільний шістнадцятковий блок             | Не застосовується |

## AmneziaWG V3.1 {#amneziawg-v31}

### Огляд {#amneziawg-v31-overview}

<font color="red">**Примітка**: Маршрутизатори GL.iNet підтримують AmneziaWG 3.1 починаючи з прошивки v4.11.1.</font>

AmneziaWG 3.1 зберігає всі механізми маскування з v2.0: випадкові префікси для кожного типу пакетів (**S1–S4**), динамічні заголовки (**H1–H4**), пакети-сигнатури перед рукостисканням (**I1–I5**) і послідовність зайвих пакетів (**Jc**, **Jmin**, **Jmax**). Нові механізми додатково ускладнюють розпізнавання трафіку за характерними ознаками:

- **Захист заголовків**: Використовує ChaCha20, щоб приховати поля заголовків пакетів WireGuard, які інакше залишалися б незашифрованими.
- **Доповнення вмісту**: Додає до транспортних пакетів даних випадкову кількість байтів у межах доступного розміру MTU.
- **Налаштовувані часові параметри**: Дає змогу задавати значення або діапазони для заміни ключа, повторних спроб рукостискання, пакетів підтримання з’єднання та пов’язаних механізмів. Для сервера й клієнта рекомендовано використовувати автоматично створені значення.
- **Випадкові кінцеві доповнення**: Додає до кінця пакетів рукостискання й транспортних пакетів даних доповнення змінної довжини, щоб урізноманітнити розміри пакетів.
- **Вимкнення відповідей Cookie**: Дає змогу пристрою припинити надсилання відповідей Cookie під час рукостискання. Пристрій і далі може отримувати такі відповіді та виконувати решту операцій рукостискання.

### Параметри {#amneziawg-v31-parameters}

В AmneziaWG V3.1 додано такі параметри.

| Параметр | Опис | Обмеження | Діапазон або значення GL.iNet |
| -------- | ---- | --------- | ------------------------------ |
| `HeaderProtectionKey` | Вмикає захист на основі ChaCha20 для полів заголовка пакета, які інакше залишаються незашифрованими | Рівно 32 байти. Якщо захист увімкнено, потрібно задати всі параметри S1, S2, S3 та S4, кожен зі значенням ≥ 12. Рекомендована комбінація: `H1=1`, `H2=2`, `H3=3`, `H4=4`. Вона вимикає механізм власних заголовків, а тип повідомлення приховує механізм захисту заголовків | 32-байтовий ключ |
| `ContentPaddingAddition` | Додає до кожного транспортного пакета даних випадкову кількість байтів із заданого діапазону | `range<uint16>`, 0–65535, min ≤ max; `0` або `0-0` вимикає функцію | 0–65535 (приклад: `10-50`) |
| `RekeyAfterTime` | Час використання поточного ключа до початку активної заміни ключа (у секундах) | `range<uint16>`, 0–65535, min ≤ max; за значення `0` або `0-0` використовується значення WireGuard за замовчуванням | 100–150 (у WireGuard за замовчуванням: 120) |
| `RekeyTimeout` | Час очікування відповіді на окремий запит рукостискання перед повторною спробою (у секундах) | `range<uint16>`, 0–65535, min ≤ max; за значення `0` або `0-0` використовується значення WireGuard за замовчуванням | 4–7 (у WireGuard за замовчуванням: 5) |
| `RejectAfterTime` | Час без отримання даних, після якого розпочинається нове рукостискання (у секундах) | `range<uint16>`, 0–65535, min ≤ max; за значення `0` або `0-0` використовується значення WireGuard за замовчуванням | 180–240 (у WireGuard за замовчуванням: 180) |
| `KeepaliveTimeout` | Час без надсилання даних, після якого надсилається внутрішній пакет підтримання з’єднання (у секундах) | `range<uint16>`, 0–65535, min ≤ max; за значення `0` або `0-0` використовується значення WireGuard за замовчуванням | 8–20 (у WireGuard за замовчуванням: 10) |
| `MaxHandshakeAttempts` | Максимальна кількість повторних спроб рукостискання | `range<uint16>`, 0–65535, min ≤ max; за значення `0` або `0-0` використовується значення WireGuard за замовчуванням | 12–18 (у WireGuard за замовчуванням: 18) |
| `RandomTrailers` | Додає змінну кількість байтів у кінці пакетів: випадкові дані в пакетах рукостискання й нулі після внутрішнього IP-пакета в транспортних пакетах. Довжина доповнення добирається динамічно, щоб не перевищити MTU жодної зі сторін | `off` вимикає функцію. Якщо функцію ввімкнено, рекомендовано задати `S1 = S2 = S3 = S4`, щоб зменшити ризик помилкового визначення типу пакета через випадкові розміри | `on` / `off` |
| `DisableCookies` | Забороняє локальному пристрою надсилати відповіді Cookie під час рукостискання. Не впливає на отримання відповідей Cookie від віддаленого вузла та решту операцій рукостискання | `off` вимикає функцію. Значення S3/H3 мають залишатися дійсними, оскільки можуть використовуватися під час приймання пакетів | `on` / `off` |

**Примітки**

* Маршрутизатор може автоматично створювати значення з діапазонів в останньому стовпці. Перемикачі `RandomTrailers` і `DisableCookies` налаштовуються окремо на кожному пристрої.
* Значення `HeaderProtectionKey` має бути однаковим на клієнті й сервері.
* Під час роботи часові значення поза наведеними діапазонами замінюються випадковими значеннями з відповідних діапазонів, тому введене значення може не застосуватися.
* `ContentPaddingAddition` і `S4` змінюють довжину транспортного пакета, але діють на різні його частини й можуть використовуватися разом.
* Захист заголовків і динамічні значення `H` можуть використовуватися разом. `H1–H4` можуть залишатися динамічними, хоча рекомендоване налаштування — `1/2/3/4`.
