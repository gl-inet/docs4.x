# Налаштування NAT {#nat-settings}

Ця функція доступна починаючи з прошивки v4.5. У v4.9 її перейменовано на NAT Mode.

---

У лівому меню вебпанелі адміністрування відкрийте **NETWORK** -> **NAT Settings** або **SECURITY** -> **NAT Mode**.

На цій сторінці можна увімкнути **Full Cone NAT** для поліпшення стабільності з’єднань між вузлами у застосунках, зокрема іграх чи потокових сервісах, а також **SIP ALG** для усунення проблем сумісності телефонних сервісів на основі VoIP/SIP.

## Full Cone NAT {#full-cone-nat}

Full Cone NAT забезпечує прямий шлях для підключення таких пристроїв, як ігрові консолі або телефони, до інших пристроїв в інтернеті, наприклад у багатокористувацьких іграх або відеовикликах.

Зовнішні пристрої отримують прямий доступ до локальних пристроїв через маршрутизатор замість проходження кількох рівнів приховування адрес. Це підвищує стабільність з’єднань між вузлами (P2P), зменшує затримку та усуває збої підключення у застосунках P2P.

**Примітка**: порівняно з іншими типами NAT ця функція може знизити безпеку, оскільки робить порти пристроїв доступними з публічної мережі.

## SIP ALG {#sip-alg}

SIP ALG (Application Layer Gateway) працює як «перекладач» маршрутизатора для сервісів зв’язку на основі VoIP/SIP, наприклад офісних стаціонарних телефонів або викликів через застосунки.

Ця функція призначена для розв’язання проблем проходження NAT. Вона змінює дані викликів для безперервного передавання через кілька рівнів NAT, які часто трапляються в мережах із кількома маршрутизаторами, наприклад основним маршрутизатором і маршрутизатором GL.iNet. Це зменшує конфлікти та запобігає перериванню викликів.

**Примітка**: несумісна або неналежно реалізована SIP ALG може погіршити якість викликів і спричинити одностороннє передавання звуку, відсутність реакції на вхідний виклик, розриви з’єднання або перенаправлення викликів безпосередньо на голосову пошту.
