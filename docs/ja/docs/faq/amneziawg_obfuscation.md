# AmneziaWG 難読化 {#amneziawg-obfuscation}

AmneziaWG は、トラフィック難読化機能を内蔵した WireGuard ベースの VPN プロトコルです。難読化パラメーターは、厳しいネットワーク検査下での検出を回避するために、トラフィックをどのように偽装するかを制御します。

以下では、AmneziaWG の概要と各バージョンの違いを詳しく説明します。

## なぜ AmneziaWG なのか？ {#why-amneziawg}

AmneziaWG の前身である WireGuard は、コンパクトなコードベースと高い効率により、高速で信頼性の高い VPN プロトコルとして広く利用されています。しかし、固定されたパケットヘッダーと予測しやすいパケットサイズにより、識別しやすいシグネチャが生まれます。DPI システムはこれらのパケットを容易に特定し、直ちに接続を遮断できます。これは、インターネット検閲が厳しい国では重大な問題です。

AmneziaWGは、元のWireGuard実装の設計のシンプルさと高い性能を引き継ぎながら、VPNトラフィックのパターンを隠す専用の難読化モジュールを追加しています。これにより、個人ユーザーと企業ユーザーのオンラインプライバシーを保護し、制限の厳しいネットワーク環境でも安定した接続を維持できます。

簡単に言うと:

- VPN の特徴を隠し、ISP、ファイアウォール、またはディープパケットインスペクション（DPI）による検出を防ぎます。

- VPN 接続を通常の Web トラフィックのように見せかけることで、制限されたネットワークでの接続安定性と成功率を向上させます。

## AmneziaWG V2.0 {#amneziawg-v20}

### 概要 {#amneziawg-v20-overview}

<font color="red">**注意**：AmneziaWG 2.0 は、ファームウェア v4.9.0 以降の GL.iNet ルーターでサポートされています。</font>

AmneziaWG 2.0 は、一連のジャンクパケット（**Jc**、**Jmin**、**Jmax**）と Init および Response パケットのランダムプレフィックス（**S1–S2**）という v1.0 の難読化機能を引き継ぎます。さらに、接続の予測可能な特徴を隠すために、次の仕組みが追加されています。

* **S3–S4**：Cookie および Data パケットのランダムプレフィックスです。v1.0 では Init と Response パケットにしかパディングが追加されないため、Cookie パケットは常に 64 バイトで、Data パケットの長さはペイロードの長さと同じでした。

* **範囲で指定する H1–H4**：各パケット種別のヘッダー値は、単一の固定値ではなく範囲から選ばれます。受信時には範囲内の値がすべて受け入れられます。4 つの範囲は重複できません。

* **I1–I5**：各ハンドシェイクの前に送信する、ユーザー定義の UDP パケットです。これにより、セッション開始時のトラフィックは WireGuard のハンドシェイクではなく、一般的な UDP プロトコルのように見えます。

これらの強化により、VPN トラフィックは検出されにくくなりながらも、WireGuard の高速性と低遅延を維持できます。

!!! Tip "AmneziaWG 1.0 と 2.0 を見分ける方法"

    **V1.0**: S3-S4 パラメーターがなく、H1-H4 は単一の固定整数です。
    
    **V2.0**: 次のいずれかの条件を満たす場合は V2.0 です。
            
    - S3-S4 パラメーターを含む
    - H1-H4 が数値範囲として設定されている
    - カスタム I1-I5 パラメーターを含む。
            
    > 注意: I1-I5 は自動生成されません。ユーザーは設定ファイルに追加行として手動で記述し、AmneziaWG のトラフィックを QUIC や WebRTC などの一般的なプロトコルのように見せることができます。

### パラメーター {#amneziawg-v20-parameters}

| パラメーター | 説明 | 制約条件 | 自動生成 |
| ------------ | ---- | -------- | -------- |
| Jc | クライアントがハンドシェイクを開始する前に送信するジャンクパケット数（トラフィック特徴検出の妨害用） | 1~128 | 4~12 |
| Jmin | ランダムなジャンクパケットの最小サイズ（バイト）。ジャンクパケットサイズを定義するために Jmax と組み合わせて設定する必要があります | 0 ≤ Jmin < Jmax < 1280 | 0 <= jmin < jmax < 1280 |
| Jmax | ランダムなジャンクパケットの最大サイズ | 0 ≤ Jmin < Jmax < 1280 | 0≤ Jmin < Jmax < 1280 |
| S1 | Init パケット用のランダムプレフィックス | 0 ≤ S1 ≤ 1132 | 15~150 |
| S2 | Response パケット用のランダムプレフィックス | 0 ≤ S2 ≤ 1188 <br> S1 + 56 ≠ S2 | 15~150 |
| S3 | Cookie パケット用のランダムプレフィックス | 0 ≤ S3 ≤ 1216 | 15~150 |
| S4 | Data パケット用のランダムプレフィックス | 0 ≤ S4 ≤ 32 | 0~32 |
| H1~H4 | パケット種別用の動的ヘッダー。v1.0 ではランダム値、v2.0 では範囲 | 5~2147483647; H1, H2, H3, H4 は互いに異なる必要があります | 5~2147483647 |
| I1~I5 | プロトコル偽装用のシグネチャパケット | 任意の16進数バイト列 | N/A |

v2.0 の難読化設定例：

```ini
[Interface]
Address = 10.1.0.2/24
PrivateKey = <client private key>
DNS = 10.1.0.1
MTU = 1420

Jc = 11
Jmin = 472
Jmax = 1277
S1 = 122
S2 = 134
S3 = 13
S4 = 13
H1 = 1318795025-1318795156
H2 = 1029272944-1029273095
H3 = 966737016-966737098
H4 = 282229905-429495047
```

参考資料: [AmneziaWG 公式ドキュメント](https://docs.amnezia.org/documentation/amnezia-wg){target="_blank"}

## AmneziaWG V3.1 {#amneziawg-v31}

### 概要 {#amneziawg-v31-overview}

<font color="red">**注意**：AmneziaWG 3.1 は、ファームウェア v4.11.1 以降の GL.iNet ルーターでサポートされています。</font>

AmneziaWG 3.1 は、全パケット種別のランダムプレフィックス（**S1–S4**）、動的ヘッダー（**H1–H4**）、ハンドシェイク前のシグネチャパケット（**I1–I5**）、一連のジャンクパケット（**Jc**、**Jmin**、**Jmax**）など、v2.0 のすべての難読化機能を引き継ぎます。さらに、トラフィックの特徴による識別を難しくするために、次の仕組みが追加されています。

- **ヘッダー保護**：ChaCha20 を使用して、通常は暗号化されない WireGuard パケットヘッダーのフィールドを隠します。
- **コンテンツのパディング**：MTU に収まる範囲で、ランダムな長さのパディングをトランスポートデータパケットに追加します。
- **タイミングのカスタマイズ**：鍵の更新、ハンドシェイクの再試行、キープアライブなどに値や範囲を設定できます。サーバーとクライアントの両方で、自動生成された値を使用することを推奨します。
- **ランダムトレーラー**：ハンドシェイクパケットとトランスポートデータパケットに可変長のトレーラーを追加して、パケットサイズをさらに変化させます。
- **Cookie 応答の無効化**：ハンドシェイクの Cookie 応答の送信を停止できます。Cookie 応答の受信やその他のハンドシェイク処理は引き続き行われます。

### パラメーター {#amneziawg-v31-parameters}

AmneziaWG V3.1 で追加されたパラメーターは次のとおりです。

| パラメーター | 説明 | 制約条件 | GL.iNet での範囲または値 |
| --------- | ----------- | ----------- | ----------- |
| `HeaderProtectionKey` | 通常は暗号化されないパケットヘッダーのフィールドを ChaCha20 で保護する | 正確に 32 バイト。有効にする場合、S1、S2、S3、S4 をすべて設定し、それぞれの値を 12 以上にする必要がある。推奨の組み合わせは `H1=1`、`H2=2`、`H3=3`、`H4=4`。この場合、カスタムヘッダー機能が無効になり、ヘッダー保護によってメッセージ種別が隠される | 32 バイトの鍵 |
| `ContentPaddingAddition` | 設定範囲からパケットごとにランダムに選んだバイト数をトランスポートデータパケットに追加する | `range<uint16>`、0–65535、最小値 ≤ 最大値。`0` または `0-0` で無効 | 0–65535（例：`10-50`） |
| `RekeyAfterTime` | 能動的な鍵の更新を開始するまでに現在の鍵を使用する時間（秒） | `range<uint16>`、0–65535、最小値 ≤ 最大値。`0` または `0-0` では WireGuard のデフォルト値を使用 | 100–150 (WireGuard のデフォルト：120) |
| `RekeyTimeout` | 個々のハンドシェイク要求を再試行するまでの応答待機時間（秒） | `range<uint16>`、0–65535、最小値 ≤ 最大値。`0` または `0-0` では WireGuard のデフォルト値を使用 | 4–7 (WireGuard のデフォルト：5) |
| `RejectAfterTime` | データを受信しない状態が続いたとき、新しいハンドシェイクを開始するまでの時間（秒） | `range<uint16>`、0–65535、最小値 ≤ 最大値。`0` または `0-0` では WireGuard のデフォルト値を使用 | 180–240 (WireGuard のデフォルト：180) |
| `KeepaliveTimeout` | データを送信しない状態が続いたとき、内部キープアライブを送信するまでの時間（秒） | `range<uint16>`、0–65535、最小値 ≤ 最大値。`0` または `0-0` では WireGuard のデフォルト値を使用 | 8–20 (WireGuard のデフォルト：10) |
| `MaxHandshakeAttempts` | ハンドシェイクの最大再試行回数 | `range<uint16>`、0–65535、最小値 ≤ 最大値。`0` または `0-0` では WireGuard のデフォルト値を使用 | 12–18 (WireGuard のデフォルト：18) |
| `RandomTrailers` | パケットの末尾に可変長のバイト列を追加する。ハンドシェイクパケットにはランダムデータ、トランスポートパケットには内部 IP パケットの後にゼロを追加する。トレーラーの長さは双方の MTU を超えないように動的に選択される | `off` で無効。有効な場合は、ランダムなパケットサイズによる種別の誤判定を抑えるために `S1 = S2 = S3 = S4` を推奨 | `on` / `off` |
| `DisableCookies` | ローカルデバイスからのハンドシェイク Cookie 応答の送信を停止する。ピアからの Cookie 応答の受信やその他のハンドシェイク処理には影響しない | `off` で無効。受信処理で使われる可能性があるため、S3 と H3 は有効な値にしておく必要がある | `on` / `off` |

**注意事項**

* 最終列の範囲はルーターに生成を任せることができます。`RandomTrailers` と `DisableCookies` はデバイスごとに切り替えます。
* クライアントとサーバーでは、同じ `HeaderProtectionKey` を使用する必要があります。
* 記載範囲外のタイミング値は、実行時に範囲内のランダムな値に置き換えられます。そのため、入力したカスタム値がそのまま適用されない場合があります。
* `ContentPaddingAddition` と `S4` はどちらもトランスポートパケットの長さを変えますが、作用する箇所が異なり、併用できます。
* ヘッダー保護と動的な `H` は併用できます。`H1–H4` は動的なままでもかまいませんが、推奨値は `1/2/3/4` です。

v3.1 の難読化設定例：

```ini
[Interface]
Address = 10.1.0.2/24
PrivateKey = <client private key>
DNS = 10.1.0.1
MTU = 1420

Jc = 11
Jmin = 472
Jmax = 1277
S1 = 122
S2 = 134
S3 = 13
S4 = 13
H1 = 1
H2 = 2
H3 = 3
H4 = 4

HeaderProtectionKey = <32-byte key>
ContentPaddingAddition = 10-50
RekeyAfterTime = 100-150
RekeyTimeout = 4-7
RejectAfterTime = 180-240
KeepaliveTimeout = 8-20
MaxHandshakeAttempts = 12-18
```
