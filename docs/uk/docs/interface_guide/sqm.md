# SQM (інтелектуальне керування чергами) {#sqm-smart-queue-management}

**Примітка**: цю функцію додано у прошивці v4.9.

Деякі моделі, зокрема Mango 2 (GL-MG1300), не підтримують SQM через недостатній обсяг пам’яті, навіть із прошивкою v4.9 або новішою.

---

У лівому меню вебпанелі адміністрування відкрийте **FLOW CONTROL** -> **SQM**.

SQM (Smart Queue Management) інтелектуально керує мережевим трафіком маршрутизатора для зменшення затримки та надмірної буферизації (bufferbloat). Це забезпечує плавнішу роботу ігор і голосових викликів.

**Примітка**:

1. Ця функція впливає лише на трафік, який проходить через маршрутизатор, коли він працює як шлюз, зокрема трафік локальних клієнтів і клієнта VPN. Вона не застосовується до вхідного трафіку, коли маршрутизатор працює як сервер VPN.
2. SQM потребує значних ресурсів, тому найкраще підходить для мереж із низькою пропускною здатністю або перевантаженням. На високошвидкісних з’єднаннях увімкнення функції може знизити максимальну пропускну здатність.
3. SQM не діє, коли маршрутизатор працює в режимі Drop-in Gateway.
4. SQM і QoS не можна увімкнути одночасно.
5. SQM несумісне з прискоренням мережі. Увімкнення SQM автоматично вимикає прискорення мережі для забезпечення стабільної роботи.

## Для прошивки v4.11 і новіших версій {#for-firmware-v411-and-above}

Увімкніть SQM за допомогою перемикача та виконайте наведені нижче дії для налаштування.

![Налаштування SQM у v4.11](https://static.gl-inet.com/docs/router/en/4/interface_guide/sqm/sqm_v4.11.png){class="glboxshadow" width=600}

1. **WAN Bandwidth**

    Вручну введіть швидкості передавання та завантаження WAN у діапазоні 1 - 10000 або натисніть **Run Speedtest**, щоб виміряти їх та автоматично заповнити поля. Для перевірки швидкості потрібне активне інтернет-з’єднання.

    ![Пропускна здатність WAN](https://static.gl-inet.com/docs/router/en/4/interface_guide/sqm/wan_bandwidth.png){class="glboxshadow" width=600}

    **Примітка**: значення в полях введення задаються в **Mbps** (мегабітах за секунду). Для довідки відображається відповідне значення в **MB/s** (мегабайтах за секунду).

2. **Queue Discipline**

    Виберіть правило керування чергами для обробки трафіку та зменшення затримки під навантаженням.

    ![Правило керування чергами](https://static.gl-inet.com/docs/router/en/4/interface_guide/sqm/queue_discipline.png){class="glboxshadow" width=600}

    - **cake**: інтелектуальне автоматичне формування трафіку з поліпшеним загальним контролем затримки (рекомендовано).

        Якщо для керування чергами вибрано **cake**, додатково доступна функція **Cake Autorate**.

        Cake Autorate зменшує або збільшує пропускну здатність CAKE у реальному часі на основі часу проходження пробних пакетів в обидва боки (RTT). Активні перевірки швидкості не виконуються; використовуються лише легкі запити ping. Функцію рекомендовано, якщо пропускна здатність WAN змінюється. Для стабільних з’єднань вона не потрібна.

        ![Автоматичне регулювання CAKE](https://static.gl-inet.com/docs/router/en/4/interface_guide/sqm/cake_autorate.png){class="glboxshadow" width=600}

        **Примітка**: Cake Autorate постійно створює фоновий трафік перевірок. Враховуйте це додаткове використання даних, якщо з’єднання має тарифікацію за обсягом.

        Налаштування за замовчуванням підходять для більшості з’єднань. Змінюйте наведені нижче параметри лише якщо розумієте їхній вплив на Cake Autorate. За потреби натисніть **Reset to Default**, щоб відновити стандартні параметри перевірок і порогові значення.

        ![Параметри перевірок і порогові значення](https://static.gl-inet.com/docs/router/en/4/interface_guide/sqm/probe_threshold_parameters.png){class="glboxshadow" width=600}

        - **Probe Server Addresses**: список IP-адрес, розділених комами, для перевірки якості мережі.

        - **Probe Interval**: коротший інтервал забезпечує швидше реагування, але збільшує використання ресурсів CPU.

        - **Concurrent Probes**: кількість одночасних перевірок не повинна перевищувати кількість серверів перевірки. Більше значення збільшує навантаження на CPU.

        - **Idle Detection Threshold**: якщо швидкість передавання падає нижче цього значення, з’єднання вважається неактивним. Значення не повинно перевищувати 25% заданого обмеження швидкості.

        - **Download Latency Threshold**: перевищення цього порогу затримки завантаження спричиняє зменшення пропускної здатності.

        - **Upload Latency Threshold**: перевищення цього порогу затримки передавання спричиняє зменшення пропускної здатності.

    - **fq_codel**: просте й ефективне справедливе керування чергами з базовим зменшенням затримки.

## Для прошивки v4.9–v4.10 {#for-firmware-v49-to-v410}

Увімкніть SQM за допомогою перемикача та задайте максимальні швидкості передавання й завантаження у діапазоні 1 - 10000 для планування трафіку. Для найкращого результату значення мають відповідати фактичній пропускній здатності інтернет-з’єднання.

![Налаштування SQM](https://static.gl-inet.com/docs/router/en/4/interface_guide/sqm/sqm.png){class="glboxshadow"}

**Примітка**: значення в полях введення задаються в **Mbps** (мегабітах за секунду). Для довідки відображається відповідне значення в **MB/s** (мегабайтах за секунду).

![Швидкості завантаження та передавання](https://static.gl-inet.com/docs/router/en/4/interface_guide/sqm/up_down_speed.jpg){class="glboxshadow"}

Для Queue Rule доступні два варіанти:

- **cake**: інтелектуальне автоматичне формування трафіку з поліпшеним загальним контролем затримки (рекомендовано).

- **fq_codel**: просте й ефективне справедливе керування чергами з базовим зменшенням затримки.

!!! Tip

    QoS дозволяє задавати пріоритети застосунків, відповідно до яких маршрутизатор розподіляє пропускну здатність. SQM дозволяє вибирати правило керування чергами.
