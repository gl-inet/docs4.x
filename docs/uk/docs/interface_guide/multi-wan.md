# Multi-WAN {#multi-wan}

<iframe width="560" height="315" src="https://www.youtube.com/embed/D1s1WScLP4s" title="Відеопрогравач YouTube" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture" allowfullscreen></iframe>

У лівому меню вебпанелі адміністрування відкрийте **NETWORK** -> **Multi-WAN**.

Налаштуйте кілька способів доступу до інтернету, щоб маршрутизатор міг швидко й автоматично перейти на інший спосіб, якщо поточний стане недоступним. Також можна використовувати кілька способів одночасно, розподіляючи мережеві з’єднання між ними у заданому співвідношенні.

Маршрутизатори GL.iNet можуть підключатися до інтернету різними способами: [Ethernet](internet_ethernet.md), [ретранслятор](internet_repeater.md), [спільний доступ до інтернету через USB](internet_tethering.md) і [стільниковий зв’язок](internet_cellular.md).

!!! Note

    1. Моделі без Wi-Fi, наприклад GL-MT2500/GL-MT2500A, підтримують лише Ethernet, спільний доступ до інтернету через USB і стільникове підключення.

    2. Моделі без порту USB, наприклад GL-B3000, підтримують лише Ethernet і підключення через ретранслятор.

    3. Деякі моделі підтримують [два Ethernet-з’єднання WAN](ethernet_port.md#dual-ethernet-wan). На сторінці Multi-WAN для них відображатиметься додатковий інтерфейс Ethernet.

## Відстеження стану інтерфейсів {#interface-status-track}

Маршрутизатори GL.iNet підтримують до 5 віртуальних мережевих інтерфейсів, але їхня кількість залежить від моделі. Наприклад, GL-MT6000 має **Ethernet 1**, **Ethernet 2**, **Repeater**, **Tethering** і **Cellular**, кожен із яких виконує окремі мережеві функції у програмно визначених конфігураціях.

Маршрутизатори використовують команду **ping** або **httping** (лише у v4.3 і попередніх версіях) для перевірки з’єднання з IP-адресою призначення та визначення доступності інтерфейсу.

Якщо інтерфейс доступний, ліворуч відображається зелена крапка; інакше — сіра.

![Стан мережевих інтерфейсів](https://static.gl-inet.com/docs/router/en/4/interface_guide/multi-wan/interface_status_track_1.jpg){class="glboxshadow"}

### Налаштування відстеження стану {#status-track-settings}

Натисніть піктограму шестерні, щоб відкрити налаштування відстеження стану окремого мережевого інтерфейсу.

Нижче показано налаштування відстеження стану інтерфейсу Ethernet. Так само налаштовуються інші інтерфейси.

![Налаштування відстеження стану інтерфейсу](https://static.gl-inet.com/docs/router/en/4/interface_guide/multi-wan/interface_status_track_2.png){class="glboxshadow"}

- **Enable Interface Status Track**: увімкнено за замовчуванням. Якщо вимкнути відстеження стану, маршрутизатор визначатиме доступність інтерфейсу за фізичним станом, наприклад за наявністю підключеного мережевого кабелю.

- **Detection Mode**: цю функцію додано у v4.5 під назвою Low Data Mode, а у v4.7 перейменовано на Detection Mode. Доступні три режими: Normal Mode, Low Data Mode і Strict Mode.

    За замовчуванням використовується Normal Mode. Low Data Mode виконує перевірку лише в разі помилки мережевого інтерфейсу, а Strict Mode визначає стан інтерфейсу лише за результатами команди перевірки публічної IP-адреси.

    Використовуйте Low Data Mode, якщо ваш тарифний план має обмежений обсяг даних. Однак відновлення з’єднання після розриву може бути дещо повільнішим, ніж у звичайному режимі. За замовчуванням цей режим увімкнено лише для стільникового інтерфейсу.

- **Track Command**: команда ping перевіряє з’єднання з IP-адресою призначення для визначення доступності інтерфейсу. У прошивці v4.3 і попередніх версіях також доступна команда httping.

- **IPv4 Track IP**: тут можна задати власну IPv4-адресу для перевірки.

!!! Note

    У деяких старих версіях прошивки, наприклад v4.3, доступні параметри **Track Interval**, **Change to Failure Condition** і **Change to Available Condition**. Починаючи з v4.5, їх вилучено та замінено на Detection Mode і Sensitivity Options.

### Параметри чутливості {#sensitivity-options}

Ця функція доступна починаючи з v4.5.

![Параметри чутливості](https://static.gl-inet.com/docs/router/en/4/interface_guide/multi-wan/sensitivity_options.jpg){class="glboxshadow"}

Чутливість визначає інтервал перевірки стану інтернет-з’єднання.

- Якщо мережа стабільна, для перегляду відео чи прямих трансляцій або ігор рекомендовано високу чутливість, щоб швидко перемикатися в разі розриву з’єднання.
- Якщо мережа нестабільна та ви завантажуєте кешовані файли, рекомендовано низьку чутливість, щоб уникнути постійних перемикань мережі та невдалих спроб підключення.

**Порада**: перехід на високу чутливість може призвести до розриву мережевого з’єднання. Змінюйте параметр обережно.

## Режими Multi-WAN {#multi-wan-mode}

Multi-WAN має два режими: **Failover** і **Load Balance**. Вони взаємовиключні, тому одночасно можна використовувати лише один.

### Аварійне перемикання {#failover}

Failover — режим за замовчуванням для кількох з’єднань WAN. Якщо активне з’єднання перестає працювати, маршрутизатор автоматично переходить на інший мережевий інтерфейс для доступу до інтернету.

![Аварійне перемикання Multi-WAN](https://static.gl-inet.com/docs/router/en/4/interface_guide/multi-wan/failover.png){class="glboxshadow"}

Задайте пріоритет кожного інтерфейсу. Якщо поточний інтерфейс перестає працювати, маршрутизатор переходить на доступний інтерфейс із найвищим пріоритетом. Щойно з’єднання з вищим пріоритетом відновлюється, маршрутизатор автоматично повертається до нього.

### Балансування навантаження {#load-balance}

Load Balance дозволяє одночасно використовувати кілька мережевих з’єднань, збільшуючи пропускну здатність і загальну швидкість передавання даних.

**Load Ratio** визначає розподіл трафіку між інтерфейсами: система призначає нові з’єднання інтерфейсам відповідно до заданого співвідношення.

![Балансування навантаження Multi-WAN](https://static.gl-inet.com/docs/router/en/4/interface_guide/multi-wan/load_balance.png){class="glboxshadow"}

Доступні два варіанти налаштування співвідношення навантаження:

- **Default Load Ratio**

    Якщо маршрутизатор одночасно підключено до чотирьох мереж — Ethernet, Repeater, Tethering і Cellular — та всі інтерфейси мають доступ до інтернету, увімкнення Load Balance зі співвідношенням 1:1:1:1 рівномірно розподіляє мережеве навантаження між ними. Система призначає нові з’єднання цим чотирьом інтерфейсам відповідно до співвідношення 1:1:1:1.

- **Customize Load Ratio**

    Якщо пропускна здатність Ethernet становить 200 Mbps, а Wi-Fi Repeater — 100 Mbps і з’єднання Tethering та Cellular неактивні, задайте співвідношення 2 для Ethernet, 1 для Repeater і 0 для Tethering/Cellular. Система розподілятиме нові з’єднання за співвідношенням 2:1, тому Ethernet оброблятиме приблизно вдвічі більше з’єднань, ніж Repeater. Порівняно з Failover це підвищує загальну ефективність передавання даних завдяки розподілу навантаження між доступними інтерфейсами.

**Примітка:** активні з’єднання або трафік не обов’язково точно відповідають заданому співвідношенню. Зі збільшенням часу використання розподіл наближається до нього.

## Сценарії використання {#usage-scenarios}

* Касова система магазину використовує дротове підключення до інтернету, а підключення через Repeater до Wi-Fi сусідніх магазинів або стільникову мережу із SIM-картою — як резервний спосіб доступу, щоб уникнути переривання мобільних платежів у разі недоступності мережевого кабелю.

* Якщо маршрутизатор підключено через Repeater до публічної мережі Wi-Fi, але швидкості недостатньо, одночасно використовуйте спільний доступ до інтернету через USB із телефона для балансування навантаження та збільшення загальної пропускної здатності.
